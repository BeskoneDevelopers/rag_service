# Как работает запрос в RAG-сервисе

## Redis Lock и TTL

После поиска API пытается записать в Redis случайный токен командой `SET ... NX EX 180`. `NX` разрешает запись только при свободном ключе. `EX` ставит срок жизни 180 секунд, чтобы ключ исчез даже при падении процесса. Оба маршрута используют один ключ. Если ключ занят, клиент получает 503.

Задача продления запускается примерно раз в 60 секунд. Lua-скрипт сверяет токен владельца и продлевает срок. Сервис прекращает генерацию, если продление не подтверждено. В `finally` другой Lua-скрипт проверяет токен и освобождает ключ. Проверка нужна, чтобы старый запрос не удалил ключ нового владельца.

## Жизненный цикл SSE

1. API проверяет JWT и компанию, затем получает контекст через Celery.
2. При наличии контекста получает блокировку до отправки HTTP-заголовков. После отправки заголовков статус ответа уже задан.
3. Каждая часть текста отправляется как событие `token`. По подтверждённому завершению проверяются номера ссылок, и `sources` закрывает успешный поток. При сбое поток закрывает `error`.
4. При отключении клиента ASGI-сервер передаёт `http.disconnect`. Обработчик отменяет работу, закрывает чтение из Ollama и освобождает блокировку. Отключение до первого события тоже обрабатывается.

Без релевантных чанков поток отправляет готовую фразу и пустые `sources`. К Ollama этот запрос не обращается.

## Ошибки Ollama и Celery

Клиент Ollama различает отказ подключения, таймаут и ошибку ответа модели. Для обычного API это 503, 504 и 502 соответственно. При обрыве установленного соединения есть одна повторная попытка до первого токена. Когда клиент уже получил текст, повтор мог бы добавить начало нового ответа в тот же поток.

Сбой очереди поиска возвращает 503, истечение времени ожидания Celery — 504, ошибка самой задачи поиска — 502. Для загрузки документа сбой постановки в очередь даёт 503 и оставляет запись со статусом `failed`, чтобы повтор той же загрузки использовал тот же ID.

## Тестирование без моделей

- `httpx.MockTransport` имитирует Ollama. Можно отдать один токен, затем оборвать соединение и проверить, что клиент получает `error` и второго запроса нет.
- Подмена embedding возвращает заранее заданный вектор. Подмена поиска задаёт оценки выше порога, на пороге и ниже него. Так видны точные границы фильтра и порядок ссылок.
- Тесты Redis подменяют команды `SET` и Lua, но запускают два настоящих асинхронных HTTP-запроса к FastAPI. Это проверяет конкуренцию и освобождение блокировки на границе маршрута.
- TTFT и Hit@5 проверяются отдельно. Для них используются установленные модели и реальные данные, чтобы измерения относились к конкретному стенду.
